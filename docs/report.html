Estimating ground-level PM2.5 across India from INSAT-3DR satellite haze

India has about 500 continuous PM2.5 monitors, almost all of them in cities. ISRO's INSAT-3DR satellite photographs the whole country every half hour. Airscope trains a model on what the monitors measure, using what the satellite sees plus weather and an atmospheric forecast, and then estimates PM2.5 for every 10 km cell of India, including the places no monitor covers.

Why this project exists

PM2.5, particles smaller than 2.5 micrometres, is India's most damaging air pollutant. The national network (CPCB's CAAQMS stations) gives accurate hourly readings, but only where a station stands. Most districts, most villages and most of the Indo-Gangetic Plain between cities have no monitor.

A geostationary satellite sees everywhere. INSAT-3DR measures aerosol optical depth (AOD): how much the whole column of air, from the ground to space, dims sunlight. AOD is not PM2.5. It counts haze at every altitude, it swells when humidity makes particles absorb water, and the same column of haze is more concentrated near the ground when the mixing layer is shallow. Turning AOD into what people breathe takes weather, physics and ground truth.

The question this project answers honestly: does INSAT-3DR add real skill over weather and the CAMS forecast alone, in places the model has never seen? In short, yes. After the final upgrade it adds about 0.08 R² in unseen regions, and it is the only model that stays accurate in unseen weeks.

  1. Read the satellite files

    Each HDF5 file holds one scan: a 551 × 551 grid of AOD at 0.1° from 45° to 100° E and 10° S to 45° N, with times in UTC. The reader decodes fill values and scale factors and crops to India. Inspecting a real file settled a conflict between MOSDAC's catalogue (650 nm, 4 km) and its algorithm document (550 nm, 10 km): the product is a 0.1° grid.

  2. Match satellite to stations

    For every scan and station, a haversine ball-tree finds the pixels within 15 km (about 3 × 3 pixels) and records their mean, spread, nearest value and the share that were cloud-free. Two scans fall in each hour. CPCB labels an hourly average by when it starts on the IST clock, which is half past the hour in UTC, so every reading is relabelled by its centre before the two sources are joined.

  3. Add weather and CAMS

    Hourly ERA5 and CAMS values are attached to each station-hour, with derived features such as the lowest mixing height in the last 12 hours, 6-hour mean wind and 24-hour rain.

  4. Turn column haze into surface haze

    Two physics corrections are computed: AOD divided by mixing height (the same haze in a thinner layer is denser near the ground), and the same divided by a humidity-growth factor f(RH) = (1 − RH)−γ (wet particles look bigger to the satellite than they weigh). Before any machine learning, these lift AOD's correlation with PM2.5 from 0.17 to 0.26.

  5. Add satellite context

    Four features describe the haze around each point: mean AOD within 50 km, the point's mean over that day's scans, its seasonal mean over all 855 scans, and today relative to usual. They come only from the satellite files and are computed identically at a station and at a map cell. This was the final upgrade.

  6. Train the model

    LightGBM gradient-boosted trees predict log(1 + PM2.5), because pollution is heavy-tailed and errors grow with concentration. Two physics guardrails are enforced as monotone constraints: the prediction can only rise with the CAMS forecast and only fall as the mixing layer deepens. Latitude and longitude are deliberately left out, so the model cannot memorise where the stations are.

  7. Test it where it has never looked

    Spatial-block cross-validation splits India into 1° squares (about 100 km) and holds whole squares out together. Delhi's dozens of stations therefore can't leak into each other's test folds. A separate temporal hold-out trains on October to December and tests on January. Every model is scored on exactly the same rows, against two baselines: the raw CAMS forecast, and the same model without the satellite.

  8. Explain each estimate

    SHAP values split every prediction into contributions from each input: how much CAMS, mixing height, today's haze or the season raised or lowered it. The app shows these as "What moved this estimate".

  9. Map all of India

    Every 0.1° cell of India is treated exactly like a station: the same AOD windows, the same context features, and weather and CAMS bilinearly interpolated from a 1.5° grid. The result is masked to India's own boundary. Sixteen scan hours from October to January were mapped.

The temporal result matters most for real use. Without the satellite, the model trained on autumn falls apart in January (R² below zero). With INSAT-3DR it keeps R² 0.40 and nearly removes its bias. The satellite sees what this winter is actually doing, not what the weather usually implies.

What drives the estimates

The final upgrade, and what didn't work

The first real-data model (v1) used only the 15 km AOD around each station at the scan hour. Two things limited it. 31% of station-hours had no AOD at all because of cloud or bright ground. And a single hour's haze says nothing about whether a place is usually hazy. The upgrade gave the model the satellite's wider view, then tested each change on its own, on identical folds:

Smearing is a textbook fix for the low bias of predicting on a log scale. Here it inflated every prediction by 58%, flipping the bias from −13 to +14 and halving R². It assumes errors are the same size everywhere, and across unseen regions they are not. It was removed.

Constraining every plausible input (wind, rain, all AOD forms) cost skill. Constraining only the two relationships that are physically certain helped. Seven variants were compared on the same folds, which slightly flatters the winner; the temporal hold-out, which none of the variants were selected on, confirms the gain (R² 0.105 → 0.404).

The Airscope app

A FastAPI server serves the prediction maps, station readings and per-point explanations. The frontend is React with MapLibre GL for the map, deck.gl for stations and labels, three.js for the loading-screen globe and framer-motion for interface motion.

  • Map: the chosen layer (model PM2.5, satellite AOD, CAMS, or the INSAT effect) drawn as a smooth colour field clipped to India, re-projected so it sits exactly on the boundary, and cross-faded between hours and layers.
  • Data sheet: India's median PM2.5 with its National AQI band and health note, and the share of land in each band. Select any point to see its estimate, the same point from the no-satellite model, CAMS and the nearest station, the inputs there and the SHAP drivers.
  • Timeline: each of the 16 mapped scan hours as a column of India's median PM2.5, with keyboard navigation and playback.
  • Loading screen: a WebGL globe that turns to India while INSAT-3DR, on its geostationary orbit at 74° E, scans it.

An accessibility audit against WCAG 2.1 AA fixed three issues before submission: faint text below 4.5:1 contrast (raised to 5.4:1 dark and 5.5:1 light), AQI band names drawn in their band colour (now ink text beside a colour swatch), and an hour selector without arrow-key support (now a proper radio group). Reduced-motion settings stop the globe spin and the logo's orbiting satellite.

Limitations

  • Urban ground truth. Nearly every CPCB station is in a city. Good scores on held-out regions show the model works in unmonitored urban areas; they cannot prove it works in villages.
  • Daytime only. INSAT AOD exists only for sunlit, cloud-free pixels, so maps exist only for the seven daytime scan hours.
  • Winter Delhi is still under-predicted. The worst stations read 170 µg/m³ on average and are under-predicted by 80 to 100. Extreme smog days are rare in the training data and partly above the satellite's retrieval range.
  • CAMS remains the strongest input. The satellite adds real skill, but the forecast still does the heavy lifting.
  • One satellite, one season. INSAT-3DS data exists for the same months but was not used, and the model has only seen October to January.
  • Coarse weather for maps. Weather on the maps is interpolated from a 1.5° grid to respect the free API limits; stations used exact points.

Next steps

Add INSAT-3DS to halve cloud gaps and double scan frequency; add a full year to learn the monsoon and summer dust; add population density and land use as static features; train a night-time model on weather and CAMS for 24-hour maps; and compare with low-cost sensor networks in rural districts.

Reproduce it

Code: github.com/charith99936/airscope. Python 3.9 with LightGBM 4.6, pandas 2.3, scikit-learn 1.6, h5py 3.14 and FastAPI; Node with React 19, Vite 8, MapLibre GL 6, deck.gl 9.4 and three.js 0.186. API keys and downloaded data are not in the repository.

./setup_env.sh                                   # Python environment
python -m aqpipe openaq-stations && python -m aqpipe openaq-fetch   # ground truth
python -m aqpipe match   --aod-dir data/mosdac --satellite 3R       # satellite at stations
python -m aqpipe build                                              # QC + ERA5 + CAMS
python -m aqpipe context --aod-dir data/mosdac --satellite 3R       # 50 km, daily, seasonal AOD
python -m aqpipe train   --table data/train_table_context.csv --out runs/winter_v2
python -m aqpipe predict --aod-dir data/mosdac --model runs/winter_v2 --out maps/winter_v2 --satellite 3R
cd web && npm install && npm run build && cd ..
python -m aqpipe serve   --maps maps/winter_v2 --model runs/winter_v2 --stations data/stations.csv --truth data/pm25_truth.csv
